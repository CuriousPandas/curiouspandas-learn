So far you've met one idea at a time, in small labs written around that idea. Real programs aren't like that. A real program starts from a problem somebody has, in plain words, and nobody tells you which idea to use.

So here's a problem somebody has.

> Four friends go away for the weekend. One pays for the hostel, another for the train, someone gets the snacks. At the end, everyone should have paid the same. Who pays whom?

You could do this on a napkin for two people. With five people and twenty receipts, you'll get it wrong and someone will be annoyed. That's a good sign you're looking at a program worth writing.

## From a problem to a plan

Don't start with code. Start with what goes in and what comes out, using a real example:

```text
Who is on the trip? Ana, Ben, Cai
Ana 90.00 hostel
Ben 30.50 train tickets
Cai 12.00 snacks
done
```

```text
Spent 132.50 between 3 people.
Cai pays Ana 32.16
Ben pays Ana 13.67
```

Now look for the problems hiding in that example, before they find you:

- **People type things badly.** `Cai lots of snacks` isn't a payment. A crash would lose everything, so it shouldn't crash. Quietly skipping it would give everybody wrong totals with no warning. So: skip it, and *say so*. That's [the errors lesson](/learn/programming/input-and-errors/).
- **Names can be wrong.** If someone types `Anna`, a careless program invents a fourth traveller. Refuse names that aren't on the list.
- **Money doesn't suit floats.** `int(float("19.99") * 100)` is 1998, not 1999: try it in any lab. So all the sums use whole **cents**, as plain integers, and only the printed output has a dot in it.
- **Totals don't always divide.** 100 cents between 3 people is 33, 33, 33 and one cent left over. That cent has to go to somebody, or the books won't balance.

Then split it into pieces you can each test alone. The pieces name themselves:

| Function | Takes | Gives |
|---|---|---|
| `parse_expense` | one line of text, and who's on the trip | a name and an amount in cents, or a `ValueError` |
| `balances` | who's on the trip, and all their expenses | each person's paid minus their fair share, in a dictionary |
| `settle` | those balances | a list of who pays whom |

Three small functions, each with an answer you can check by hand. The rest is reading input and printing, and that's already written for you.

<GoDeeper title="Does this always use the fewest payments?">
No, and this is worth knowing. The method in the worked version, largest debtor pays largest creditor, never needs more than one fewer payment than there are people with a balance, because each payment clears at least one of them, and the last clears two. But that isn't always the minimum. Say Ana is owed 4, Ben 3 and Cai 2, while Dee owes 4 and Eli owes 5. The worked version below makes four payments: Eli pays Ana 4, Dee pays Ben 3, then Dee and Eli each pay Cai 1. Three would do: Dee pays Ana 4, and Eli pays Ben 3 and Cai 2. Finding the true minimum means finding groups of people whose balances add up to exactly zero, and that gets expensive as the group grows. For a holiday, this is close enough. This site's tests check that example by running it.
</GoDeeper>

This is one correct answer out of many. These three go in place of the unfinished ones.

```python
def parse_expense(line, people):
    words = line.split()
    if len(words) < 2:
        raise ValueError(f"can't read: {line}")
    if words[0] not in people:
        raise ValueError(f"nobody called {words[0]} is on this trip")
    return (words[0], to_cents(words[1]))

def balances(people, expenses):
    total = sum([cents for name, cents in expenses])
    share = total // len(people)
    extra = total % len(people)
    balance = {}
    for i, person in enumerate(people):
        balance[person] = -share
        if i < extra:
            balance[person] -= 1
    for name, cents in expenses:
        balance[name] += cents
    return balance

def settle(balance):
    left = balance.copy()
    payments = []
    while True:
        owed = max(left, key=lambda p: left[p])
        owes = min(left, key=lambda p: left[p])
        if left[owed] == 0:
            return payments
        amount = min(left[owed], -left[owes])
        payments.append((owes, owed, amount))
        left[owed] -= amount
        left[owes] += amount
```

One form here is new. `max(left, key=lambda p: left[p])` finds the person with the largest balance: `key=` says what to compare them by, and `lambda p: left[p]` is a small function with no name, which takes a person and gives back their balance.

</details>

## What to remember

- Start from what goes in and what comes out, with a real example, before any code.
- Look for what will go wrong in that example, and decide what should happen.
- Split it into pieces you can check by hand, and write the tests as you go.
- Know what your program doesn't do. Then you can decide whether that matters.
