"Agent" is the exciting word, so it gets used for everything. Anthropic's guide to building them draws a useful line between two kinds of system:

- **Workflows** are "systems where LLMs and tools are orchestrated through predefined code paths". You decide the steps; the model fills each one in.
- **Agents** are "systems where LLMs dynamically direct their own processes and tool usage". The model decides the steps.

Its advice is to start with "the simplest solution possible, and only increasing complexity when needed", because "agentic systems often trade latency and cost for better task performance". An agent can handle the unexpected. A workflow is cheaper, faster and does the same thing every time - which is what you want when the job is the same every time.

## The common workflow shapes

The same guide names five patterns. In plain terms:

- **Prompt chaining** - step one's output becomes step two's input: draft, then check, then translate.
- **Routing** - one call sorts the input, and each kind goes to its own handler: refunds here, password resets there.
- **Parallelisation** - several calls at once: check a reply for tone, facts and policy separately, then combine.
- **Orchestrator-workers** - one call splits a job into pieces it can't predict in advance and hands them out.
- **Evaluator-optimiser** - one call writes, another grades, and they go round until the grade passes.

Only the last two let the model decide much. The first three are ordinary code with model calls in the slots.

## Try all three

Twenty tickets: order questions, refunds, password resets, and three odd ones that fit none of those. Each design runs over all twenty. Costs use Claude Sonnet 5.5's list price on 2026-10-30 ($2 per million input tokens, $10 per million output). The token counts per call are illustrative, but their shape is real: a fixed handler costs the same every time, and an agent's turns get dearer because each one re-reads everything before it.

<WorkflowLab />

What the numbers say:

- **The fixed workflow** handled 17 of 20 for about $0.13, with no ticket taking more than 2 calls. The three odd tickets went to the nearest handler and got confidently wrong answers - the worst kind of failure, because nothing errors.
- **The agent** handled all 20, but cost about $0.58, over four times as much, and its slowest ticket took 8 calls. Most of that money went on tickets the workflow had already handled correctly.
- **The mix** handled all 20 for about $0.31. Note what it didn't fix: its slowest ticket still took 9 calls, the classifier plus the agent. The odd cases are still slow. They're just the only slow ones.

<Callout kind="trap">
The workflow's three failures didn't look like failures. A misrouted ticket gets a fluent, polite, wrong answer. If your workflow has no "other" route, find out how often real tickets fall between your categories before you trust its success rate.
</Callout>

## When an agent is worth it

Before reaching for an agent, ask:

1. **Can you write the steps down?** If yes, write them as code. The model fills in the hard parts of each step.
2. **What does a wrong step cost?** An agent chooses its own actions, so its mistakes are harder to predict. Anthropic recommends "extensive testing in sandboxed environments, along with the appropriate guardrails" - that's the [next lesson](/learn/agents/guardrails-and-evals/).
3. **How many will you run?** The cost difference above is small on 20 tickets. At 50,000 a month it decides whether the project pays for itself.
