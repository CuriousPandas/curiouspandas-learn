Linux was built for many people sharing one machine, and every file still carries the answer to one question: **who may do what to me?** `ls -l` shows it as ten characters at the start of each line:

```text
-rwxr-xr--  1 panda dev  64 Oct 30 09:00 deploy.sh
```

The first character is the type (`-` a file, `d` a directory). The next nine are three groups of three, for three kinds of people:

| Letters | Who | In this example |
|---|---|---|
| `rwx` | the **owner** (`panda`) | read, write and run it |
| `r-x` | the file's **group** (`dev`) | read and run, not change |
| `r--` | **everyone else** | read only |

Each letter is a bit: **r** = 4, **w** = 2, **x** = 1. Add them per group and you get the three digits people type: `rwxr-xr--` is **754**.

## Grant exactly what's missing

`chmod` changes the bits, either as digits (`chmod 754 deploy.sh`) or as a change to make: who (`u` owner, `g` group, `o` others, `a` all), then `+`, `-` or `=`, then the letters. `chmod u+x deploy.sh` adds one bit, run-for-the-owner, and touches nothing else.

<Callout kind="trap" title="chmod 777 makes the error go away">
`777` is `rwxrwxrwx`: anyone on the machine may run the file, and anyone may **rewrite** it. The script now works, and the next person to edit it decides what it does the next time you run it. It's the file-system version of granting cluster-admin to make a "forbidden" error disappear, and [the cluster-access lesson](/learn/security/cluster-access/) meets the same trap one level up.
</Callout>

## Folders have the same bits, with different meanings

On a **directory**, `r` lets you list the names in it, `w` lets you create, delete and rename entries in it, and `x` lets you go into it and reach anything inside.

That gives one surprise worth remembering: **deleting a file needs write permission on the folder, not on the file.** A read-only file in your own folder can still be deleted by you. A file you could rewrite completely can't be deleted if its folder isn't yours.

<Callout kind="real">
Real systems add more than the nine bits: `root` skips most checks, `sudo` lets you act as root, a `umask` trims the permissions new files are born with, and special bits like setuid and the sticky bit on `/tmp` (anyone may create files there, but only the owner may delete them) change the rules in specific places. The sandbox has none of these, so it can show the nine bits on their own.
</Callout>

<DoItForReal id="linux-perms-real" needs="terminal" xp={20}>

On Linux, a Mac or WSL:

```bash
printf 'echo it runs\n' > hello.sh
ls -l hello.sh        # -rw-r--r--: nobody may run it
./hello.sh            # Permission denied
echo $?               # 126: found, but not executable
bash hello.sh         # runs: bash only needs to READ the file
chmod u+x hello.sh && ./hello.sh
ls -l /etc/shadow     # Linux/WSL: password hashes, unreadable to you
```
