Every program starts with three streams already open: **standard input** (where it reads), **standard output** (where it writes its results) and **standard error** (where it writes complaints). In a terminal, input is your keyboard and both outputs are your screen.

The pipe, `|`, rewires that. In `a | b`, everything `a` writes to standard output becomes `b`'s standard input. Neither program knows; each just reads and writes lines. So tools that each do one small job - keep matching lines, cut out a column, sort, count - combine into answers none of them could give alone.

## Redirection: where the output goes

Pipes connect programs. **Redirection** connects a program to a file:

- `> file` writes output to a file, **replacing** what was there.
- `>> file` **appends** to the end.
- `< file` feeds a file in as input.
- `2> file` sends standard error to a file. `2> /dev/null` throws errors away.

<Callout kind="trap" title="cat notes.txt > notes.txt empties the file">
The shell sets up `>` before the command starts, and `>` begins by truncating the file to nothing. By the time `cat` opens `notes.txt` to read it, it's already empty. Write to a new file and rename it, or append with `>>`.
</Callout>

<Callout kind="real">
Real `sort` and `ls` order text by your **locale**, so `B` may come before or after `a` depending on your settings. The sandbox orders by raw bytes, like `LC_ALL=C sort`. Its text tools are checked against GNU coreutils on every change, and the counts and spacing you see here (`uniq -c` pads its numbers to seven characters) are the real ones.
</Callout>

<DoItForReal id="linux-pipes-real" needs="terminal" xp={20}>

Your own shell keeps a history. Ask it which commands you use most:

```bash
history | cut -c 8- | sort | uniq -c | sort -rn | head
```

Then the classic "which files are biggest here?":

```bash
du -a . 2>/dev/null | sort -rn | head -5
```
