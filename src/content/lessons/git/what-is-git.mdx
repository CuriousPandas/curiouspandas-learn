Every project you'll ever work on changes. Files get edited, deleted, renamed, broken and fixed again. **Git** is the tool almost every software team uses to remember all of it. It can tell you what the project looked like last Tuesday, who changed this line, and give you back the version from before you broke it.

The idea underneath is simpler than its reputation:

1. You work on files as normal, in your **working tree**.
2. When you have something worth keeping, you put those changes in the **staging area** (`git add`).
3. Then you take a **snapshot** of everything staged (`git commit`). The snapshot is permanent, and it gets a name.

That name is the interesting part. Git doesn't number snapshots 1, 2, 3. It runs the snapshot's exact contents through a hash function called SHA-1 and uses the 40-character result as the name. Same contents, same name, on every computer in the world. Change one letter and you get a completely different name.

The three boxes under the terminal are the three places a file can be: your working tree, the staging area, and the last commit. Watch your file move from box to box as you go.
</Callout>

## Why staging exists

Beginners often ask why you can't just commit straight away. Staging lets you choose what goes into a snapshot. Say you fixed a bug and also left some debugging junk lying around: you stage the fix, commit it, and the junk stays out of history. One commit should be one idea.

<Callout kind="trap">
`git commit -am "msg"` stages every *tracked* file that changed, then commits. It never picks up brand-new files, because untracked files aren't tracked yet. "I committed but my new file isn't there" is nearly always this.
</Callout>

<Callout kind="real">
Real git puts all of this in a hidden `.git` folder next to your files, and it opens a text editor when you leave out `-m`. This sandbox has no editor, so it always asks for `-m`.
</Callout>

<DoItForReal id="git-first-commit-real" needs="terminal">

On your own machine, with [git installed](https://git-scm.com/downloads):

```bash
mkdir panda && cd panda
git init
echo "hello, panda" > hello.txt
git add hello.txt
git commit -m "my first commit"
git log
git hash-object hello.txt
```

`git hash-object hello.txt` prints the same hash the playground showed for the same contents. Try it.
