In the Kubernetes track you met the core idea: write down what you want, and a controller keeps making it true. **GitOps** takes one more step. The "what you want" lives in a **git repository**, and a controller in the cluster keeps pulling from it and applying it.

What you get:

- **Every change is a commit.** It has an author, a reason and a review, and you can revert it.
- **The cluster can be rebuilt from the repo.** Lose the cluster and point a new one at the same repository.
- **Hand edits become visible**, because live state that doesn't match git is *drift*.

That last point depends entirely on what's doing the reconciling, and that's where people get caught.

## Three reconcilers, one kubectl edit

**Flux** is a CNCF GitOps toolkit with separate controllers for separate jobs. Two of them matter here:

- A **Kustomization** applies plain manifests. The Flux docs say each reconciliation, every `interval`, applies the manifests again, "correcting any existing drift in the process". With `prune` turned on, it also deletes objects that were removed from git.
- A **HelmRelease** installs a Helm chart. Its `interval` re-checks the *release* against the spec. Comparing the live objects is a separate, optional feature: `.spec.driftDetection` is opt-in.

<Callout kind="real">
The tilt platform installs about 35 charts as Flux HelmReleases and sets `driftDetection` on none of them. A `kubectl edit` to something a chart deployed stays until the next upgrade of that release. Helm 3's three-way merge then compares the old manifest, the live state and the new manifest, and puts the chart's own fields back. Knowing which reconciler owns an object tells you whether your hotfix lasts an interval or a release.
</Callout>

## Pin your versions

One more habit from the tilt repo, in a comment on every HelmRelease:

> Pinned, not "*": Flux re-resolves an unbounded version on every reconcile, so the platform rebuilt later is not the one built today.

GitOps promises you can rebuild from the repo. With a floating version, you can rebuild *something*. With a pinned one, you rebuild *the same thing*.
