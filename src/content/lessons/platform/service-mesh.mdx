Inside a cluster, services call each other constantly. By default that traffic is plain, unencrypted and unmeasured, and any pod can call any other. A **service mesh** puts a layer of infrastructure underneath every call. It gives you:

- **mTLS:** every connection is encrypted, and *both* sides prove who they are with certificates the mesh issues and rotates. No application code changes.
- **Telemetry:** who called whom, how often, and how fast.
- **Policy:** rules like "only the frontend may call the payments service".

The tilt platform runs **Istio in ambient mode**. Istio's original sidecar mode, which it still supports, injects a proxy into every pod. Ambient mode uses a shared per-node proxy called **ztunnel** for encryption and connection-level telemetry, and optional **waypoint** proxies for request-level features such as HTTP routing and request counts. Lab 06 adds a waypoint for exactly that reason: ztunnel encrypts and forwards traffic but doesn't count requests.

## The catch: it's invisible

Because the app doesn't change, the app can't tell you whether it's in the mesh. When the tilt platform was first built, **zero namespaces** carried the label that enrolls workloads. ztunnel ran on every node and every check was green, and not one workload was in the mesh. Kiali's mesh view was the only thing that showed it.

Configured-but-inert is worse than absent, because it reads as protection.

## How you join, and how you prove it

You enroll a namespace by labelling it `istio.io/dataplane-mode=ambient`. The proof is on the **pod**, not the namespace:

```bash
kubectl -n hello get pod -l app.kubernetes.io/name=hello \
  -o jsonpath='{.items[0].metadata.annotations.ambient\.istio\.io/redirection}'
#   enabled   -> traffic is captured by ztunnel
#   (empty)   -> not in the mesh
```

<Callout kind="trap" title="Two sources disagree - check, don't trust">
Istio's documentation says ambient mode adds pods to the mesh "with no need to restart applications". Tilt lab 03 restarts the pod after labelling the namespace and says capture is decided when the pod starts. We haven't settled which holds on every setup. What both agree on is the check above: after labelling, read the annotation, and restart the pod if it doesn't say `enabled`.
</Callout>
