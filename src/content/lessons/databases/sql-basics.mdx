A relational database keeps data in **tables**: rows of the same shape, each column with a name. You don't tell it *how* to find anything. You describe the rows you want in **SQL**, and the database works out how to get them.

The console below runs **real SQLite**, the database built into every phone and browser, compiled to WebAssembly and running in your tab. There's no server and nothing to install, and nothing you type leaves your machine.

The zoo has three tables:

- `keepers`: who works here, and on which shift.
- `pandas`: each panda, with a `keeper_id` saying who looks after it.
- `feedings`: what each panda ate, how much, and on which day.

## Four words do most of the work

```sql
SELECT name, age          -- which columns
FROM pandas               -- from which table
WHERE age > 10            -- which rows
ORDER BY age DESC;        -- in what order
```

Without `ORDER BY`, rows come back in whatever order is cheapest for the database. That's often the order they were inserted, until one day it isn't. If order matters, say so.

`GROUP BY` folds rows that share a value into one row, so you can total them: `SUM(kg)`, `COUNT(...)`, `AVG(age)`.

## Joins: one question, two tables

Each panda row stores its keeper's `id`, not their name. To show names you **join** the tables on that key:

<Callout kind="trap">
`COUNT(*)` counts rows. `COUNT(p.id)` counts rows where `p.id` isn't NULL (SQLite's own documentation draws exactly this distinction). After a `LEFT JOIN`, a keeper with no pandas still produces one row, full of NULLs, so `COUNT(*)` reports 1. A report that says every keeper looks after at least one panda is the kind of mistake nobody notices for months.
</Callout>

<DoItForReal id="db-sql-real" needs="terminal">

macOS and most Linux systems ship the `sqlite3` shell (on Debian or Ubuntu: `sudo apt install sqlite3`). Try the `COUNT` trap on your own machine:

```bash
sqlite3 :memory:
```

```sql
.mode box
CREATE TABLE keepers (id INTEGER PRIMARY KEY, name TEXT);
CREATE TABLE pandas (id INTEGER PRIMARY KEY, name TEXT, keeper_id INTEGER);
INSERT INTO keepers VALUES (1, 'Mei'), (2, 'Ravi');
INSERT INTO pandas VALUES (1, 'Bao', 1), (2, 'Lin', 1);
SELECT k.name, COUNT(*), COUNT(p.id) FROM keepers k LEFT JOIN pandas p ON p.keeper_id = k.id GROUP BY k.id;
```

Ravi's row shows `1` and `0` side by side.
